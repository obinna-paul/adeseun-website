# adeseun-website

Personal-professional site for Adeseun Oyeneye (Managing Director and author). Currently in the strategy/blueprint phase — see repo docs once added for the Brand North Star and narrative architecture.

## Standing rule: always apply the vendored skills, unmentioned

`.claude/skills/` contains design and animation skills vendored specifically for this project (see `.claude/skills/THIRD_PARTY_SKILLS.md` for sources and licenses). Apply the relevant ones automatically on every piece of work in this repo — copy, layout, CSS, animation, review — without waiting to be asked or told which skill to use. This is a standing instruction for the whole project, not a one-time request.

- **taste-skill** (`.claude/skills/taste-skill`) — the anti-slop rulebook. Check every page/section design and every content blueprint against its hard rules (eyebrow restraint, hero discipline, no duplicate-intent CTAs, serif/palette discipline, layout-repetition bans, etc.) before calling anything done.
- **emil-design-eng** (`.claude/skills/emil-design-eng`) — animation and interaction craft. Apply the animation decision framework, correct easing curves, transform/opacity-only performance rule, and component-polish details to any CSS or motion code.
- **impeccable** (`.claude/skills/impeccable`) — broader design workflow (mode selection: Persuade / Operate / Read / Experience, shape/critique/audit/polish commands). Use its mode framework when deciding how a given page should behave, and its craft floor before shipping UI.
- **brandkit** (`.claude/skills/brandkit`) — brand system consolidation. Use once her visual assets (logo, headshots, book covers, palette) are available.
- The remaining Emil Kowalski skills (`animate`, `apple-design`, `ask-sonner`, `pick-ui-library`, `prototype`, `review-animations`, etc.) — pull in whichever is relevant to the task at hand (e.g. `pick-ui-library` before adding a UI dependency, `review-animations` before shipping motion).

When a skill's rule gets violated in something already written (blueprint copy, CSS, layout), fix it proactively and note what changed and why — don't just flag it and wait.
